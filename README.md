# EASUN MQTT Bridge

Experimental transparent MQTT proxy for the RWB1 datalogger used by some EASUN
iSolar SMH III inverters. It forwards the original connection to the vendor
cloud, validates and decodes Modbus RTU frames, and publishes confirmed
telemetry to a local MQTT broker using Home Assistant MQTT Discovery.

The vendor app can remain operational. The bridge never stores or displays the
datalogger MQTT credentials and does not support parameter writes. Optional
local polling is restricted to one confirmed read-only telemetry block; locally
generated requests and their responses are not forwarded to the cloud.

> Status: the Home Assistant app and two-second local polling have been
> validated on one SMH III 4.2 kW inverter with an RWB1 datalogger while keeping
> the vendor app operational. The project remains experimental and must not be
> used as the only monitoring or control source.

Installation requires both Home Assistant and OpenWrt changes. Do not configure
the firewall from this summary alone; follow the complete
[`installation guide`](docs/INSTALLATION.md), starting with passive mode and a
reversible dry run.

## Architecture

```text
RWB1 datalogger -> OpenWrt -> EASUN MQTT Bridge -> vendor cloud broker
                                      |
                                      +-> local Mosquitto -> Home Assistant
```

Traffic redirection must be limited to the datalogger IP address and the
observed MQTT destination and port. Network rules depend on the OpenWrt topology
and should initially be applied temporarily so they can be removed easily.

## Home Assistant

The [`easun_bridge`](easun_bridge) directory contains an app for Home Assistant
OS. It automatically uses the service credentials generated by the official
Mosquitto Broker app; credentials are not stored in the app configuration or
written to its logs.

For standalone execution, local broker credentials are supplied only through
environment variables when required:

```text
EASUN_LOCAL_MQTT_USERNAME
EASUN_LOCAL_MQTT_PASSWORD
```

Start the proxy with `--local-mqtt-host <broker-address>`. Never place
credentials on the command line, in the repository, or in logs.

Only confirmed fields documented in [`REGISTER_MAP.md`](REGISTER_MAP.md) are
published. Fields that remain ambiguous are explicitly marked as medium
confidence.

`poll_interval` controls local polling. The recommended value for the tested
RWB1 is `2.0` seconds; `0` keeps the bridge fully passive. Before active polling
can begin, the bridge must observe a legitimate cloud request and learn its
private envelope. That envelope is stored in `/data` with restricted
permissions and may be included in Home Assistant app backups.

## Known limitations

- Only the read block starting at `0x1195` is allow-listed for local polling.
- Compatibility with other dataloggers or firmware revisions must not be
  assumed.
- An initial cloud connection is required to learn the private request envelope.
- OpenWrt routing rules are installation-specific and must restrict redirection
  to the datalogger and the vendor MQTT broker.

Tested hardware is listed without serial numbers or other private data in
[`COMPATIBILITY.md`](COMPATIBILITY.md).

## Installation

- Follow the complete [`installation guide`](docs/INSTALLATION.md).

- Complete the private [`hardware and software inventory`](docs/HARDWARE_SOFTWARE_INVENTORY.md)

- Use the [`troubleshooting guide`](docs/TROUBLESHOOTING.md) before collecting
  logs or packet captures.
- Review the [`sources and evidence policy`](SOURCES.md) for standards,
  official documentation, upstream revisions, and test-evidence boundaries.

## Privacy and security

- Never submit packet captures, credentials, MAC addresses, device identifiers,
  or complete MQTT topics.
- Start in passive mode and keep a local way to remove the traffic redirection.
- The project does not implement Modbus writes.

See [`SECURITY.md`](SECURITY.md) before reporting a vulnerability.
